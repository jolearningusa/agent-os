# Medical Agent：实施与验证计划

日期：2026-11-01。关联 [开发设计](../design/medical-agent.zh-CN.md)。
所有里程碑当前均为 **未开始**。文档检查通过不代表这些功能验收通过。

## 工作规则与完成证据

按 M0 → M1 → … → M9 顺序交付；每个里程碑可切成小 PR，但每次仅推进一个有
稳定依赖的实现切片。当前文档 PR 评审合并后再建立实现分支，合并须用户授权。

每个实现 PR 提供：需求/验收 ID、可重复命令、合成 fixture、期望与实际结果、
失败用例、版本、迁移/回滚说明。M0 建立 `make check` 统一门禁；之后每个 PR
运行其全部检查，不跳过失败。外部服务 smoke test 与无网络确定性测试分开。

角色由项目负责人安排：工程负责可执行检查，领域医生负责医学标准与盲评。
真实病例/个人信息不得进入代码、日志、PR 或评测 fixture。没有临床负责人时
可推进合成实验，但不能声称诊断准确率合格或进入真实患者试点。

## M0：项目骨架、契约和评测基线

交付：ADR 固定实验技术栈、字段与状态定义；业务 API、worker、前端骨架；数据库
迁移；模拟 ModelProvider；统一 `make check` 和 CI；50–100 个合成问题的初始集。
为医生辅助、报告解释、证据不足、越权分别建立样例；不能让模型自行生成唯一真值。

- V00：全新环境按 README 启动；`make check` 运行格式、lint、类型、单元、集成、
  构建及文档链接检查，CI 与本地命令一致。
- V01：无提供方密钥时运行模拟流程，无真实模型网络请求。
- V02：迁移新建数据库成功；从上一 schema 的合成快照升级并恢复成功。
- V03：记录临床质量门槛、重复运行次数、成本和延迟目标及批准人；这些数值在
  真实评估前固定。未确认的临床阈值必须标为待定，不能伪造通过。

退出条件：骨架可复现、契约已评审、基线集版本固定。下一步只实现 M1。

## M1：身份、诊疗事件和证据版本

交付：认证接口、医生/患者角色、诊疗关系、Encounter/Evidence、私有附件上传；
上传和证据新增有幂等键；合成医生确认关键事实界面。

- V10：患者 A 枚举患者 B 的 ID，报告、附件、问答、音频入口均拒绝且不泄漏正文。
- V11：客户端伪造 tenant 或医生角色无法提升权限；撤权后旧链接不可访问。
- V12：两个并发更新基于相同旧版本，只接受符合并发规则的一次提交；不丢失证据。
- V13：重复上传请求不生成重复证据；错误类型/超限/恶意文件被拒绝。

退出条件：授权负面测试全部通过，证据可溯源；不接入真实患者。

## M2：PMC 连接器与可替换检索

交付：KnowledgeSource 契约、PMC 适配器、许可清单、公开资料快照、索引版本和
引用定位；初始成人 2 型糖尿病语料。实现第二个内存适配器验证可替换性。

- V20：用 mock HTTP 固定分页、限流、重试、超时和 malformed 响应，结果可重复。
- V21：真实小批量 smoke test 返回可定位全文与许可；不符合许可或范围的资料不入库。
- V22：同一契约测试可运行 PMC fixture 与内存源，Harness 无需修改。
- V23：专家标记问题的相关证据被检索到；报告召回与来源支持情况，不用检索相似度
  冒充医学准确率。
- V24：撤回/删除文档使索引与缓存失效；不完整索引不能发布。

退出条件：每段证据具备 source ID、版本、许可与引用位置，检索失败可解释。

## M3：可信状态机与模型适配器

交付：RunStore、状态转换白名单、worker 租约/fencing、检查点、统一模型契约；
模拟模型和一个真实提供方，先验证最短医生草稿流程。真实付费调用启用前，
实现事务型预算预留/结算及未知用量阻断；M7 再完成双模型优化与全面压力测试。

- V30：所有非法状态转换拒绝；同一幂等请求返回同一个 Run。
- V31：在检索后、调用前、调用后/持久化前注入崩溃；恢复不丢失已确认状态，
  未知提供方结果不盲目重试。
- V32：过期 worker 无法写回结果，取消后的任务不能重新发布。
- V33：结构化结果、截断、schema 错误、超时、取消和 usage 缺失均有明确处理。
- V34：医生产生新证据版本后旧 Run 过期，新 Run 固定新证据，保留历史引用。

退出条件：能恢复和停止，故障时不产生可签发的无效草稿。

## M4：校验、医生审阅与签发

交付：结构/事实/引用/冲突校验、带证据的草稿、医生修改与差异展示、独立签发
事务、不可变报告、审计和 outbox。患者尚不自动获得生成中正文。

- V40：注入不存在的引用、反向结论、单位错误和缺失证据，拒绝或转补充流程。
- V41：校验服务异常时不发布；有限重试达到上限后停止。
- V42：新证据与旧草稿签发竞争，事务拒绝旧证据版本；修改摘要不一致时拒绝。
- V43：只有有诊疗权限的医生可签发；重复签发幂等；报告修订不覆盖原件。
- V44：worker 在签发事务后重启，报告不重复，通知逻辑幂等；通知失败可重试。

退出条件：完成“合成病例 → 草稿 → 模拟医生签发”端到端演示及全部负面用例。

## M5：患者 App/PWA 与报告问答

交付：登录、报告列表/详情、修订提示、文字问答、通知、医生联系路径；移动屏幕
可用。患者问答绑定已发布报告，只向前端发送进度和经校验答案。

- V50：患者接口无法读取草稿；通知正文不含诊断内容，权限撤销后无法打开。
- V51：抓取 SSE/HTTP 响应，校验前没有答案正文；校验失败不泄漏原文。
- V52：回答保留报告的否定、时间和不确定性，不编造新增医嘱。
- V53：问答过程中报告修订，交付前发现版本变化并重新生成或明确旧版来源。
- V54：新症状/紧急风险/超范围问题进入预设流程；普通术语问题仍能正常解释。
- V55：桌面与移动视口走通完整流程；离线/断网有明确状态，重连不重复提交。

退出条件：四个核心角色路径可演示，临床负责人尚未批准时仅合成展示。

## M6：报告截图与语音

交付：截图 OCR、关键字段确认；STT 转写、文本确认、校验后 TTS、停止/重听。
语音提供方走统一隐私和费用策略；原生移动客户端和临床影像分析继续延期。

- V60：模糊/旋转/错患者/缺页截图触发提示；数字、单位、否定词逐字段核对。
- V61：噪声和口音合成音频集测整体转写及医学实体错误；关键低确定性信息要求确认。
- V62：TTS 输入等于通过校验的文本版本；音频内容复核数字、单位、否定词一致。
- V63：校验失败时零音频输出；取消中止播放；STT/TTS 失败仍可使用文字。
- V64：删除录音后相关派生缓存按保留策略处理，跨患者请求音频失败。

退出条件：模态专项指标达到预先约定标准；未通过的能力保持关闭。

## M7：预算与质量约束下的模型路由

交付：共享预算账本、定价版本、规则路由、两档模型、有限升级、版本隔离缓存。
在新增付费调用路径前先让这些路径经过 BudgetService；M3 起已有基本调用上限，
本阶段完成已有事务型账本与优化策略的全面验证。

- V70：并发任务竞争同一余额，预留总额不超过可用额度；重复结算不重复扣费。
- V71：账本不可用/价格未知时拒绝；超时后不立即释放未知费用；对账可追溯。
- V72：重试、校验、摘要和语音调用都计入对应成本；切换 session 不重置任务额度。
- V73：跨模型用同一事实和证据重建请求；引用和用量不丢失，不传递专属推理状态。
- V74：固定数据与缓存条件，对比强模型基线、便宜模型基线、自适应策略。
  统计所有失败/升级费用、合格率、严重错误、p95 延迟与人工修改量。

退出条件：安全/授权用例全过；达到预设质量要求后才判断是否节约成本。
没有测出优势也记录真实结果，不降低质量门槛以通过验收。

## M8：事件反馈、离线改进与版本发布

交付：LearningCandidate、错误归因、医生审核、独立留出集、AgentRelease、
影子执行与回滚；初期仅改变知识/检索/提示/路由，不自动训练模型权重。

- V80：医生一次修订不影响其他患者，也不直接写入全局知识。
- V81：错误/恶意反馈被隔离；没有使用授权的事件不能进入学习流程。
- V82：同患者/事件族不跨调优集和留出集；每次评测记录不可变版本。
- V83：候选退化时发布失败；审核缺失时发布失败；在途 Run 固定旧版本。
- V84：发布后回滚，新 Run 使用旧策略；已签报告、撤权和删除状态不被回滚覆盖。

退出条件：可完整演示一次候选被拒绝、一次被批准、一次安全回滚。

## M9：临床评审与受控试点前准备

交付：领域医生独立盲评、部署/数据处理 ADR、运行手册、备份恢复、应急关闭、
性能与故障报告。确认实际使用目的和适用的机构/监管要求后决定试点范围。

- V90：按任务和人群分层报告事实、引用、重要遗漏及合理拒答，不只给平均分。
- V91：真实数据处理条件未完成时，环境开关阻止真实患者模式。
- V92：数据库、模型、语音故障时安全停止或回退文字，不输出未校验结果。
- V93：恢复备份、撤权传播、发布回滚和人工接管演练通过。

退出条件：临床/工程负责人签署试点范围和通过标准；无已知严重失败。
小样本实验通过不等于临床有效性证明，也不自动授权上线。
