## 目标与使用场景

开发者在本仓库运行一条命令，使用预定义配置启动固定版本的 Hermes fork，连接
本地 Ollama，创建 session 并进行多轮对话。通过本地页面逐次查看模型上下文的组成、
来源、顺序、裁剪和压缩过程，以及实际发给模型的请求。

本实验统一使用 Hermes，L0 固定其 fork 和提交版本，并验证可运行性与上下文采集点。
Hermes、Ollama 模型服务和查看器分别管理，项目自有配置与观察事件保持稳定。

本计划提出先行开展通用本地实验，供医疗 Agent 后续选型与工程验证使用。
本修订接受后先执行 L0a/L0b 的工程探针，再推进 L1–L5；L0a ADR 明确与医疗 M0
的衔接。实验观察结果作为医疗工程输入，医疗功能仍按 M0–M9 门禁实施。
原有医疗验收仍单独跟踪。实验输入使用人工合成内容，首版限定单机、单用户；允许该用户并发多个 session。

- D4 本地推理接入。验证聊天、流式、工具循环及失败处理，检查辅助模型调用的去向。
- D5 上下文事件。按 session、turn、model call 记录组装来源与最终请求。
- D6 本地查看器。展示调用时间线、上下文分块、版本及相邻调用差异。
- D7 实验基线。提供合成任务、固定运行配置、结果导出和 Hermes 的回归测试。

下列命令和路径为计划接口，随 L0 ADR 固定后落地。

```sh
./scripts/harness doctor --config configs/local-hermes.json
./scripts/harness up --config configs/local-hermes.json
./scripts/harness status
./scripts/harness down
```

## L0a 决策与复现清单

交付 D1/D2 的决策部分。ADR 固定目标平台、Hermes fork/commit、许可证、模型与硬件、
运行方式和隐私策略。初始建议采用受限容器运行 Harness、宿主机 Ollama；具体网络
拓扑和 CPU/GPU 可用性在目标机器确认。工具默认禁用，后续仅注册受控 fixture 工具。

ADR 须在目标平台上先验证出站白名单能否实现。部分桌面容器运行时不提供按地址和
端口的出站过滤，可能需要内部网络加代理，或宿主机防火墙规则。ADR 记录所选机制、
验证方法和备选方案。L0a 用最小网络 canary 验证所选隔离机制，无需先安装 Hermes；
验证范围、目标平台和结果写入 ADR。L0b 探针随后复用该隔离方式。

无法强制真实模型路径隔离时，允许继续 mock 开发。L23/L36 分别保存 mock 与真实
Ollama 环境结果，mock 通过只关闭对应 mock 子项；真实路径保持 blocked，L2/L3
及首个可用版本均保持未完成。真实模型运行必须等该环境的隔离验证通过。
L36 的文件/工具隔离子项仍可在实际沙箱单独验证，不能随网络子项一并豁免。

验收 ID 保留原编号，L00–L54 为验收项，L0–L5 为里程碑；新增项按阶段顺延。

- L01 fork commit 可获取，许可证可追溯；提交锁、依赖锁及可用的包/镜像摘要可校验。
- L03 ADR 填写本地实验与医疗实施顺序、正文调试授权、数据目录、权限、保留期限和
  删除方式。私有目录 0700、文件 0600、调试数据保留 7 天仅为建议值，不是决定，
  最终取值由 ADR 确认。

退出条件是两项验收证据和 ADR 评审记录齐备，随后进入 L0b。

## L0b 配置、检查与采集可行性探针

交付配置 schema、最小事件 schema、可重复 mock 探针及检查入口。拟定路径为
`configs/schema.json`、`schemas/context-event.json`、`harness.lock.json`、
`scripts/check_docs.py` 和探针 fixture。每项分小 PR 顺序交付。

探针不依赖 L1 的启动器。L0b 为探针提供最小运行方式：按 `harness.lock.json` 获取
固定源码，用手工脚本在隔离目录安装锁定依赖并启动 mock 会话。该脚本只服务探针，
不承诺接口稳定；L1 交付正式安装与生命周期后取代它，并复用同一锁文件。这样 L02
可先于 L1 验证采集能力，避免启动器与探针互相等待。脚本及其配置须入库，依赖
安装阶段可联网；执行 mock 探针时只允许本地 mock 地址，并清空继承的模型凭据。
按一条记录在 README 的命令从空实验目录复跑，保存 commit、配置 hash、退出码
及接收端断言结果。L1 替换后复跑同一 fixture，并核对观察契约，随后移除旧入口。

- L00 固定非法配置 fixture 覆盖模型缺失、无效端口和未固定源码，均拒绝并报告字段。
- L02 在固定 Hermes commit 上执行一次含工具循环的 mock 会话。接收端保存请求，
  采集端保存组装来源和最终请求，逐字段断言一致，并关联同一 session/call。
  强制触发摘要路径，验证辅助请求被采集；不可触发时记录阻塞，禁止宣称全覆盖。
- L04 `make check` 与 CI 执行同一无网络命令，覆盖当时已存在的组件；通过故意破坏
  fixture 证明 CI 会失败，修复后通过。
- L05 事件正反例覆盖必填字段、版本、父调用关系和调用状态，非法事件拒绝。
- L06 入库文档检查脚本校验相对链接、尾随空白、围栏、验收 ID 唯一性及引用存在；
  用临时坏文档验证失败退出码，再接入 `make check`。

L02 是进入 L1 的 go/no-go 门禁。通过要求是组装来源、最终请求、工具循环和辅助
调用均有可核对记录。失败先评估小范围 fork 补丁、包装调用边界或调整 Hermes 版本，
记录维护成本后重跑。若只能采集最终请求，需另行评审缩小后的观察范围再继续。

退出条件是 L00/L02/L04–L06 全部有可重复通过证据。完整采集能力仍在 L3 实现。

## L1 命令行启动与生命周期

交付 D3 和可运行的 D1/D2。脚本负责获取固定源码、创建独立运行目录、安装锁定依赖、
生成配置和启动 Harness。实例状态记录进程身份、端口、源码版本及配置 hash。
Ollama 的既有服务单独检测，停止操作仅终止本脚本拥有的进程。

拟定文件为 `scripts/harness`、Hermes 启动适配器和本地状态目录规则。
启动默认绑定 loopback。安装所需下载与运行时模型访问分别说明。

验收 L10–L14：

- L10 干净环境按 README 完成安装和启动，状态返回真实可访问的地址。
- L11 重复启动、端口占用、依赖缺失和安装中断均有明确处理。
- L12 停止后仅释放本实例资源，已有 Ollama 服务可继续使用。
- L13 同一用户创建 A/B 两实例，断言端口、配置目录、session 数据库、状态文件及
  进程身份分别独立；重启 A 后保留已知消息，B 的数据 hash 不变。
- L14 有效配置、版本和日志路径可查询，凭据被隐藏。

退出条件是开发者能稳定启动、停止并重新进入同一实验实例。

## L2 Ollama 模型连接

交付 D4。preset 选择一个已下载的本地模型，固定 endpoint、上下文和输出限制、
超时及最大调用次数。检查模型能力与实际服务容量，验证协议字段兼容。
辅助摘要、压缩和其他模型调用同样使用配置的本地路径。

验收 L20–L25：

- L20 合成首轮写入随机标记，第二轮 mock 接收端断言包含首轮用户消息与模型回答，
  顺序符合 fixture；真实模型 smoke test 另行记录结果。
- L21 流式响应和一次受控、无外部副作用的工具循环完成。
- L22 服务不可达、模型缺失、超时、取消及截断产生明确状态，重试受次数限制。
- L23 在强制网络白名单环境仅允许指定 Ollama 地址和端口，DNS 及其他出站拒绝；
  已下载模型的问答与辅助调用仍完成。访问公网 canary 必须失败，策略及请求记录留证。
- L24 记录配置容量、可核验的服务容量和 usage；无法确认的值标记 unknown。
  估算记录 tokenizer 名称/版本、模板假设及与 usage 的差值。调用前预留输出空间。

- L25 使用逐渐增长的固定长输入与首尾标记探测上下文边界，记录请求、服务配置、
  usage 和返回。已知超限输入在调用前拒绝；来源不明的截断结果标记疑似并阻止进入
  成功基线。Token 差值和模型漏答只能作为线索，须结合服务侧证据判断。

退出条件是 L20–L25 全部通过，mock 和真实模型证据分别归档；L23 真实路径
存在 blocked 时，本阶段保持未完成。

## L3 每次调用的上下文采集

交付 D5。身份层级采用 session → turn → model call → attempt，并记录父子关系。
用户一轮请求中的工具循环、重试和摘要调用分别编号。压缩调用及压缩后的主调用
通过事件引用关联。

每次调用记录以下信息：

- 组装贡献。system/developer 指令、历史、记忆、检索片段、工具结果及其来源与顺序。
- 上下文变更。新增、裁剪、摘要、替换的事件及前后引用。
- 最终请求。适配器转换后的 messages、tools、模型名与生成参数。
- 运行元数据。Harness commit、配置 hash、时间、延迟、finish reason 和 usage。

在组装层和发送边界分别采集。模型服务内部聊天模板和 tokenization 如无法观测，
页面明确标为不可观测。提供方 usage 与本地 Token 估算分别存储。

调试正文仅在显式开启的合成数据模式保存。普通日志保持无正文，数据留在被 Git
忽略的私有本地目录，带保留期限、删除命令和访问控制。使用 L0a 选定的沙箱强制约束工具：
只读挂载 fixture，独立可写临时目录，移除宿主 home、凭据及容器 socket 挂载，
限制出站到指定本地服务。fixture 工具按名称和参数白名单注册。默认关闭消息平台、外部插件及自动学习写入。

验收 L30–L34：

- L30 用接收端 fixture 逐字段比对采集的最终请求与实际收到的请求。
- L31 多轮、工具循环、压缩和重试均能关联到正确 session 与调用。
- L32 同一用户并发 A/B session，各写不同随机标记，断言请求与事件不包含对方标记；
  中断后留下明确 terminal 状态或 incomplete 标记。
- L33 使用合成凭据检测日志、事件和导出，确认凭据过滤与正文开关生效。
- L34 删除 session 调试数据后，相关正文、缓存和查看器数据按策略清理。

- L35 事件和导出包含 `schema_version`、event ID、单调序号、实例/session/turn/call/
  attempt ID、parent call ID 和时间；新旧 fixture 均可读取。相同主版本允许新增
  可选字段，未知主版本明确拒绝并提供升级或迁移提示，保留原文件。
- L36 在工具执行测试中尝试读宿主凭据路径、写只读 fixture 和访问公网，均被执行
  环境阻止；工具正常读取指定 fixture 的正例通过。
- L37 观察存储不可写、磁盘配额耗尽或事件写入失败时，该次调用禁止标记采集完整，
  实验停止并返回明确错误。记录有界大小与 hash，裁剪内容显示 truncated。

退出条件是 L30–L37 全部通过，可核对来源、最终请求和采集完整性；L36 按网络、
文件、工具边界分别留证，真实运行环境存在 blocked 时本阶段保持未完成。

## L4 本地 Context Inspector

交付 D6。提供只读页面，展示 session 列表、调用时间线、上下文来源、分块顺序、
最终请求和相邻调用差异。压缩前后可跳转，未知来源和缺失用量显式展示。
查看器绑定 loopback，使用本地会话鉴权，默认关闭跨域访问。

```sh
./scripts/harness inspect --session <session-id>
```

验收 L40–L44：

- L40 固定 fixture 逐字段核对 session/turn/call/attempt ID、父调用、序号、角色、
  来源、分块顺序、模型、配置 hash、时间、usage、finish reason 与完整性状态。
- L41 三个 fixture 分别验证第二轮历史、工具结果及压缩替换；页面 diff 与预设
  新增/删除/替换块 ID 一致，点击可定位原始事件。
- L42 事件缺失、流式中断及 unknown usage 均有可见状态。
- L43 未授权、非法 Origin/Host 及跨站导出请求均拒绝。仅接受明确 loopback Host。
  浏览器页面只使用 HttpOnly、SameSite 会话 cookie，凭据不进入 URL，页面脚本
  无法读取；状态变更和导出请求使用 Origin 校验与 CSRF token。命令行工具可另用
  授权头，两种凭据使用独立校验路径并拒绝交叉使用。明确区分 HttpOnly 会话
  cookie 与页面可读取的 CSRF token，后者绑定当前会话。
  首次登录由终端显示短时、单次配对码，用户在本地页面手工提交；成功后作废配对码
  并轮换会话。配对入口校验 Host/Origin、限制尝试次数；过期/重用/跨站提交拒绝。
  退出和重启使旧会话失效，CLI 凭据也不得建立浏览器会话。

- L44 工具返回及模型文本注入 HTML/script fixture，页面按文本安全渲染；脚本执行
  标记不得触发，导出文件名与路径不能越出数据目录。

退出条件是 L40–L44 全部通过，固定 session 可追溯且负面访问用例通过。

## L5 Hermes 实验基线与回归验证

交付 D7。固化单轮、多轮、工具循环和长上下文合成任务，记录模型版本/摘要、
生成参数、硬件、缓存条件、重复运行次数和所有尝试。使用已接入的 Hermes、
统一事件格式和查看器建立回归基线，支持之后评估配置及上下文策略变更。

```sh
./scripts/harness test --suite context-baseline
```

验收 L50–L54：

- L50 同一任务集可在固定 Hermes 版本和配置下重复执行；配置变更可追溯并比较结果。
- L51 报告任务通过情况、调用数、Token、延迟、截断及失败原因。
- L52 完整记录摘要、重试等辅助开销，缺失统计显式说明。
- L53 确定性 mock 回归通过，真实模型重复实验保留波动与原始版本记录。
- L54 同一任务集、版本、模型和生成参数下，开启和关闭采集各完成 N 次配对运行。
  N 在测量前登记为正整数，记录预热次数、缓存处理和运行顺序；交替先后顺序，使用
  独立会话并恢复同一初始状态。由独立测试驱动记录成功数、失败数和总耗时，关闭
  正文采集时该驱动仍可用。延迟统一从提交到完整响应，落盘耗时另报。
  报告各组中位数、离散程度、配对差值、事件体积及采集失败数，N 太小时标注探索性
  结果。真实模型波动可能影响差值，保留原始结果，避免直接从总延迟扣除估计开销。
  关闭采集的运行只参与开销实验；上下文完整性基线只接收采集开启且完整的运行。

退出条件是能复现 Hermes 的上下文组织与实验结果。之后再规划质量约束下的 Token
优化及医疗配置接入，实验数据用于评估具体策略的效果。

## PR 切片与依赖

交付顺序为 L0a → L0b → L1 → L2 → L3 → L4 → L5。L0–L4 构成首个可用版本。
每次只开展一个有稳定依赖的 PR，前一 PR 合并并同步 main 后再开始下一项。

建议每个 PR 仅引入一项可验证能力，通常涉及 2–5 个实现文件；行数作为评审参考。

1. L0a 交付决策 ADR；L0b 分为配置/事件 schema、文档检查及 CI、mock 采集探针。
2. L1 分为固定源码与安装、启动与健康检查、停止与恢复。
3. L2 分为连接与单轮、多轮与流式、工具循环及失败测试。
4. L3 分为事件格式、最终请求采集、来源与压缩关联、隔离与清理。
5. L4 分为时间线、上下文详情、差异与导出。
6. L5 分为任务基线、回归检查、配置实验报告。

实现 PR 提供对应验收 ID、命令、fixture、期望与实际结果。先以 mock 覆盖确定性
失败路径，再执行显式选择的本地模型 smoke test。配置与上游代码补丁分别追踪。
代码回滚恢复上一固定版本和配置；数据格式变化需兼容读取或提供迁移/恢复方案。

## 完成状态与证据

每项验收记录 fixture/输入版本、平台与环境、配置及代码 hash、命令、预期、实际结果
和状态。状态采用 pass、fail、blocked、not-run；待补证据记为 blocked 或 not-run。
同一验收含多个子项时全部通过才能记为 pass。每个 PR 附证据清单并更新本计划，
里程碑按其退出条件完成。mock 与真实模型证据分栏，避免完成状态相互覆盖。

## 工作量、维护与进一步优化
