# 资源感知 Harness：三个产品方案

研究整理日期：2026-11-01。状态：待评审的产品方案，不是已接受的架构决策。

后续方向已收敛到 [医疗 Agent 开发设计](../design/medical-agent.zh-CN.md) 与
[实施验证计划](../plans/medical-agent-implementation.zh-CN.md)。本文保留早期产品
比较；医疗实验采用自建 Harness，后续以评审接受的专门设计为准。

## 结论

推荐先验证**预算感知的业务助手**，将上下文优化作为其内部能力；当客户确有
数据驻留或已有硬件利用需求时，再验证本地与云端协同部署。

三个方案分别面向业务用户、开发团队和私有部署客户，可以共享底层接口，
但不应同时建设三个产品。核心目标是：在客户的资源和权限约束内，完成更多
合格任务。主要指标是每个合格任务的总成本，而不是单纯减少 Token。

本文结合 [landscape 研究](agent-os-landscape.md) 和
[参考架构](agent-os-reference-architecture.md)，保留早期产品比较。医疗实验的
入口以医疗开发设计为准：自建可信后端 Harness。下文的 OpenClaw 入口是当时的
比较方案，只作为通用平台对照，不覆盖医疗设计。Hermes 仍只作记忆与技能生命周期
参考，RRSI 仅用于离线优化。Deep Agents 等作为运行时适配器的实验候选。
实施前需通过 ADR 确认运行时、语言、存储、部署和客户隔离方案。

以下市场判断和技术组合属于待验证假设；没有运行成本基准，也不承诺节省比例。

## 共同需求与架构约束

- 区分资源类型：累计输入/输出 Token、单次上下文窗口、货币预算、TPM/RPM
  限额、任务截止时间、硬件容量和人工审核时间，不能用一个数替代全部约束。
- API 调用权限和可用额度必须来自客户明确授权的接口；不能假设消费级订阅
  可兑换 API Token，或允许跨账户共享额度。
- 使用版本化的客户配置记录目标、资料权限、允许的模型和工具、费用/Token
  上限、延迟目标、审批规则和数据驻留要求。模型不能修改自己的权限与预算。
- 模型调用前经过 Privacy Gateway；受保护值映射保存在 Token Vault；工具
  副作用由 PolicyEngine 和 FulfillmentExecutor 授权执行。
- 检索前执行租户和文档 ACL；索引、缓存、记忆和产物保持同等隔离。
- Session、Task、Run、Workflow 和 Schedule 保持独立；运行时可替换，项目拥有
  身份、预算、任务、隐私、记忆和审计契约。
- 记忆/技能写入先作为候选；通过隐私、污染、评测和人工评审后才能发布。
  遥测默认只记录用量、状态和不透明引用，不记录提示词、正文或个人信息。

## 方案一：预算感知的业务助手（优先）

### 用户与价值

面向小企业客服、运营团队，以及需要整理资料的个人。先选择一个重复、可核验的
工作流：根据授权知识库生成客服回复草稿。客户定制业务规则、语气、知识来源、
预算和升级条件；个人版本可复用相同机制处理自己的资料问答。

价值假设：客户愿意为合格草稿、可预测支出和更少人工修改付费。差异化来自
任务策略和客户规则的适配效果，而不是统一模型 API 或聊天界面。

### 最小可行版本与执行策略

1. 一个经过认证的入口、一套合成知识库、一个版本化的客服 AgentDefinition。
2. Privacy Gateway 处理输入；授权检索获得最少必要证据。
3. 对稳定且完全匹配的已审核答案进行受权限和文档版本约束的复用。
4. 使用便宜模型生成草稿；规则检查必填事实、引用有效性和禁止事项。
5. 检查未通过且仍有预算时，最多升级一次到强模型；不依赖模型自报信心。
6. 输出经过 DLP 检查的草稿，附引用、完成状态和用量；不自动发送邮件或修改工单。

MVP 接入一个提供方的两个模型档位；先用规则路由，积累任务数据后再评估学习型
路由。原文证据和确定性校验仍是必要条件；模型评审不能代替事实验证。

### 技术候选与工程范围

- OpenClaw 通过插件或工具集成入口，不 fork 核心；Deep Agents/LangGraph 可作为
  项目自有 AgentRuntime 后面的实验适配器，不同时维护多个生产运行时。
- LiteLLM 或 Bifrost 二选一用于模型网关；项目 BudgetLedger 管理整个任务的预算。
- 借鉴 DeerFlow 的 Token 预算中间件；用 Promptfoo 或自有测试执行器评测。
- 先实现 CustomerProfile、BudgetLedger、ContextBuilder、ModelRouter 和
  OutcomeEvaluator；沿用已有 Task/Run/CheckpointStore 边界。
- 原型可采用单进程 worker 和事务型本地数据库；生产多 worker 选型另立 ADR。
  预算与检查点必须持久化，不能只放内存。

### 风险与验证

低价模型可能产生更多返工；校验与升级本身也要计费。预算耗尽时保存检查点，
明确标记未完成，禁止把截断文本当成合格结果。验证并发超支、重试重复收费、
限流、提供方超时、引用错误、提示注入和跨租户访问等负面路径。

主要验证：相同任务集上，在预先约定的质量要求内，是否降低每个合格草稿的成本，
并减少或保持人工修改时间。商业验证是客户是否持续使用并愿意付费。

## 方案二：上下文优化与评测组件

### 用户与价值

面向已有 RAG、知识助手或内部智能体的开发团队。提供可嵌入的组件，输入任务、
授权证据引用和上下文限制，输出带来源的精简上下文与可解释的选择结果。

价值假设：客户愿意在保留原有系统的情况下，为更好的上下文利用率和可复现的
质量/成本证据付费。难点是保留关键例外、数字和引用，而不仅是缩短文本。

### 最小可行版本与技术候选

- 先支持文档问答：授权过滤后选段、去重、按任务相关性排序，预留输出空间，
  超大工具结果只传递摘要和受权限控制的产物引用。
- 安全规则和必要业务约束固定保留，不交给压缩器删除；资料明确标记为不可信内容。
- 先用确定性选段，LLMLingua 为可关闭的压缩适配器；压缩不通过验证则回退原文
  选段或明确报告上下文不足，不静默丢弃关键事实。
- Promptfoo 执行固定任务回放；DSPy 仅离线优化选择/生成策略，使用独立留出集。
- 接口候选：ContextRequest、ContextPackage、SourceRef、EvaluationReport。
  每份上下文保留文档修订、权限范围、策略版本和可定位的引用。

### 边界、风险与产品路径

授权发生在任何内容读取与候选选择之前；ACL 不可判定时拒绝读取。缓存键包含
租户、权限范围、文档版本和策略版本；撤权与删除使派生缓存失效。压缩不能作为
隐私脱敏或提示注入防御的替代品。

验证关键事实、数字、否定与例外保留、引用定位、撤权、删除传播和压缩失败回退。
将压缩、嵌入、重排、摘要和评测费用计入总成本，避免出现 Token 减少但成本增加。

可以从方案一内部模块开始；只有外部开发团队确有接入需求时，才独立包装为 SDK
和可选托管服务。首版不建设聊天产品、全套知识库或新的向量数据库。

## 方案三：本地与云端协同的私有助手

### 用户与价值

面向有明确数据驻留要求、已有电脑/服务器，或网络条件受限的团队。
根据任务类型、数据分类、机器容量、截止时间和客户政策，选择本地执行、
授权的云端调用、排队或人工处理。

价值假设：客户愿意为隐私边界、可控部署和现有硬件利用付费。总成本必须包含
硬件折旧、电力、运维和延迟，不能把本地推理视为免费。

### 最小可行版本与技术候选

- 一台客户设备、一个本地模型、一个云端适配器；不建设集群或购买 GPU。
- llama.cpp 负责本地推理；部署前独立确认模型权重许可证、内存需求和硬件表现。
- 本地完成文档分类和提取；只有允许离开环境的最小必要数据可经 Privacy Gateway
  发送至云端。严格禁止外发的任务只能本地完成、暂停或转人工。
- 复用项目 ModelProvider、PolicyEngine、BudgetLedger、队列和检查点；网关沿用
  方案一的单一选型。OpenClaw 提供入口；Hermes 仅作为记忆/调度行为参考。
- 用户画像和记忆可查看、修改和删除；首版不启用自动记忆合并或自动技能发布。

### 风险与验证

本地小模型质量、吞吐和工具调用能力不足时，不能绕过驻留策略自动云端回退。
本地处理同样需要沙箱、凭据隔离和最小权限。离线同步要保留任务幂等键，
副作用结果不明确时使用既有 unknown 状态，不能盲目重放。

验证网络中断、机器重启、模型不可用、内存不足、云端拒绝、任务取消、跨租户
缓存及敏感数据外发阻断。上线门槛是目标硬件达到约定质量/延迟要求，禁止外发
测试无泄漏，并得到客户对部署成本与运维责任的明确接受。

先做付费试点或单客户部署验证；客户没有硬件和驻留需求时，不优先选择此方案。

## 共享的预算与恢复机制（待设计确认）

BudgetLedger 属于可信服务，不由模型持有管理凭据。建议新增预算策略、预留与
结算记录，关联 principal、tenant、task、run、policy version 和不透明调用 ID。
持久化部署前必须补充版本化 schema、迁移和恢复设计。

1. 调用前原子检查并预留输入、最大输出和其他可计费项的保守上界；任务和租户
   两级额度必须一起满足。定价未知、无法限制的计费项或账本不可用时拒绝新调用。
2. 重试、摘要、校验、子任务和付费工具共用额度；重试每次有独立 attempt，禁止
   同一请求被重复记账。外部提供方凭据不可被其他路径绕过账本使用。
3. 调用后核对实际用量；超时或流式取消不能假设费用为零，不立即释放未确认预留。
   定时对账处理崩溃遗留预留，保留异常供人工检查。
4. 内部授权上限可以严格控制；提供方计费延迟、价格变化或统计误差可能导致账单
   偏差，需要安全余量与告警，不能承诺外部账单绝对零超支。
5. 预算不足时停止新调用并保存检查点。先沿用 waiting_input，记录结构化原因
   budget_exhausted；补充授权或预算后重新检查权限再恢复，不新增隐式终态。
6. 重置时间和时区明确配置；不能通过创建新 session、子任务或切换模型重置额度。

## 评测、实施顺序与选择标准

三个方案共用一个小型评测底座，评测工具不是第四个同时建设的产品。

1. 先准备 50–100 个合成任务和公开/合成文档，覆盖简单、复杂、证据不足、
   注入、越权和预算不足。真实客户内容不进入源码、日志或评测集。
2. 在调整策略前固定训练/调优集和留出集；预先记录质量门槛、预算、重复运行次数、
   延迟目标和允许的质量差异，不根据结果倒推通过标准。
3. 比较强模型基线、低价模型基线和自适应方案，固定数据、模型版本、价格快照和
   缓存条件；如提供方不能固定版本，记录该限制和运行日期。
4. 记录合格率、事实/引用错误、人工修改时间、p95 延迟、总 Token、总费用、
   预算拒绝和未完成任务。每个合格任务成本 = 全部尝试的成本 / 合格任务数；
   包含失败、重试、升级和校验，合格任务为零时不报告有限的单位成本。
5. 安全负面用例必须通过；质量低于预设要求时不得以成本下降宣告成功。
   小样本用于方向验证，报告波动和局限，不作为生产效果保证。
6. 优先完成方案一的受控试点，再决定是否开放方案二接口或进行方案三部署。
   后续实施按仓库流程逐个 PR 推进，不提前开启依赖未合并契约的实现 PR。

商业选择依据：有业务用户愿意试用则选方案一；有现成系统且明确需要 SDK 的
开发客户则选方案二；有驻留政策与合适硬件的付费客户则选方案三。

## 兼容、上线与回滚

本次仅增加研究文档与导航，不安装依赖、不修改运行行为、不引入数据迁移。
后续实现采用显式开关和版本化配置，先影子评测，再人工审核草稿，再小范围试点。
预算账本和隐私/权限检查不可被回滚开关关闭；关闭优化时仅可回到满足同样约束
的基线模型策略，或暂停任务。回滚技能和上下文策略不恢复已删除的个人记忆。

## 开源来源与采纳条件

以下来源于本次及前序研究；外部文档会变化。最终依赖需在 ADR 中固定版本/提交、
许可证、模型权重使用条件、维护状态和安全检查结果。开源代码不代表托管服务免费，
也不代表企业功能全部开源。

- [OpenClaw](https://github.com/openclaw/openclaw)：沿用既有入口/控制面建议，
  属于 2026-10-23 基础研究，不把它当作多租户安全边界。
- [Hermes](https://github.com/NousResearch/hermes-agent)：沿用既有记忆和技能参考。
- [RRSI](https://github.com/google-research/rrsi)：沿用既有离线优化边界。
- [Deep Agents 官方概览](https://docs.langchain.com/oss/python/deepagents/overview)：
  本次核对其规划、文件上下文、记忆与审批能力，作为可替换运行时候选。
- [DeerFlow 预算中间件](https://github.com/bytedance/deer-flow/blob/main/backend/packages/harness/deerflow/agents/middlewares/token_budget_middleware.py)：
  本次核对存在预算控制代码；是否覆盖跨任务并发账本需独立验证。
- [LiteLLM 预算文档](https://docs.litellm.ai/docs/proxy/users)：本次核对其预算依赖
  数据库记账；不能据此假设它提供任务全生命周期的严格预留机制。
- [Bifrost](https://github.com/maximhq/bifrost)：前序研究中的替代网关候选，
  部署前核对开源/商业功能边界，本次未做性能或版本对比。
- [RouteLLM](https://github.com/lm-sys/RouteLLM)：前序核对的路由参考，本次页面
  重访失败；不据此宣称当前维护活跃，采用前需再次核验与校准。
- [LLMLingua](https://github.com/microsoft/LLMLingua)：本次核对压缩项目；
  厂商或论文压缩比不是本项目的实测收益。
- [DSPy](https://github.com/stanfordnlp/dspy)：本次核对其程序优化能力，限离线实验。
- [Promptfoo](https://github.com/promptfoo/promptfoo)：本次核对评测/安全测试用途。
- [llama.cpp](https://github.com/ggml-org/llama.cpp)：本次核对本地推理组件，
  不对任何客户硬件的速度与成本作保证。
