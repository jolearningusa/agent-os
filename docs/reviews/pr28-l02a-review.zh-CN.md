## 发现

### F1：脏源码检查看不到被忽略文件（低）

`audit_source` 使用 `git status --porcelain`，该命令不列出被 `.gitignore` 忽略的文件。
在临时仓库复现：被忽略的 `evil.pyc` 仍被报告为干净。L02b 将以源码路径导入 Hermes，
被忽略的 `.py`、`.pyc`、`.pth` 或插件文件不会被审核发现。当前源码目录经
`--ignored` 查询为空，所以本 PR 的证据成立。

建议：L02b 开始前，审核改用 `--ignored` 或维护一份允许名单，并补一条回归测试；运行
探针时设置不写字节码，避免合法导入产生的缓存使检查失败。

### F2：Python 哈希的出处不一致（信息）

设计文档称该哈希核对自 uv 内置下载元数据；本次改以 GitHub release 资产摘要核对，两者
一致（`f15ec3d1…`）。建议文档同时写明两个来源，便于复核。

### F3：审核不重算已安装文件哈希（信息）

文档已如实说明：分发包哈希由 uv 安装时按 uv.lock 校验，之后的只读审核只比对包名与
版本。安装后若有人改动 site-packages 中的文件，该审核不会发现。对 L02a 范围可以接受；
若 L02b 的探针要被当作可信基线，需另行加入。

### F4：本机路径仍作为证据的一部分存在于忽略目录（信息）

原始日志留在忽略目录且不入库，符合规范。清理与 512 MiB 配额执行器尚未实现，当前
目录约 736 MiB；PR 已写明属于 L1/L3，此处只提醒，不要求本 PR 处理。
