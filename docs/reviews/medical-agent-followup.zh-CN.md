## 本次发现及已写入的修改

### F1：基础预算测试晚于真实调用，高优先级

M3 要求事务账本，但并发和账本故障验收集中在 M7；按原顺序实施可能先接入收费
模型再发现扣费竞态。将 V70/V71 基础用例设为 M3 真实付费启用门禁，M7 保留
扩展压力测试和模型成本对比。默认模拟、真实付费显式启用。

验收：两个任务抢同一余额、重复结算、未知价格、账本故障和 UNKNOWN 对账；
拒绝路径必须断言提供方调用次数为零。结果未知的已调用路径则保持预留且不重放。

### F2：早期版本契约依赖 M8，高优先级

Run 在 M3 已引用 AgentRelease，但其交付集中在 M8。提前定义最小不可变版本清单，
M3 即绑定完整实验版本；M8 只增加离线候选、审核和发布自动化。新增 V04/V36。

验收：清单 hash 可复核、缺项拒绝、配置变化不影响在途 Run，撤权仍优先于版本固定。
这不要求提前建设发布平台。

### F3：隐私最小化没有覆盖检索提示注入，高优先级

合法文献和附件也可能带有指令文本。去标识及 ACL 解决数据访问问题，不能保证模型
不服从资料内指令。补充内容信任边界和 V25；首版不开放任意 URL 获取。

验收：注入忽略系统规则、跨患者读取和越权工具调用 fixture；检查 trusted policy、
工具执行记录及患者响应。单靠提示词声明不能作为通过证据。

### F4：医生编辑与校验版本未明确绑定，高优先级

已有签发 hash 检查，但应明确医生编辑后不能沿用旧校验结果。新增修订、摘要与
校验绑定约束及 V45。编辑和签发竞争时必须拒绝旧结果，再校验当前修订。

验收：修改正文后沿用旧通过记录、校验异常、并发签发均不能生成 SignedReport。
人工审阅不能替代权限、结构和隐私检查；临床规则批准状态仍单独记录。

### F5：紧急提示缺少不依赖模型的交付路径，中高优先级

#6 明确了保守文案，但未明确模型超时/无预算时如何交付。补充确定性输入规则和
常驻求助入口，新增 V57。命中规则直接返回固定模板；未命中仍需输出校验。

验收：风险 fixture 在模型不可用和预算耗尽时仍得到模板；模型调用次数为零。
普通术语问题仍走正常问答。仅验证已配置路径，不把有限规则当急症识别保证。

## 实施阅读边界

可行性复核后补充三条，避免把门禁读成当时还不存在的能力：

1. M3 清单里的校验版本是结构、权限和输出隐私检查。临床规则在书面确认前使用显式
   「待定」版本。缺项拒绝不要求提前完成 M4。
2. V25 的通过证据是资料未升为系统指令，且权限、工具和签发未被改写。模型仍可能把
   注入文本写进草稿；草稿正文由 M4/M5 校验。
3. 真实付费前只强制 V70 与 V71。V72–V74 依赖语音和双模型，仍在 M7。M8 交付的是
   发布流水线；清单 schema 不从 M8 才开始存在。

## 下一阶段小步交付

下一实现 PR 仍限 M0。按以下顺序逐个 PR 交付，前一 PR 合并后再开始下一项。
每步建议只新增一个可验证能力，通常修改 2–5 个生产文件；行数不是硬门禁，
迁移与事务不可为缩小 diff 而拆成不安全的中间状态。下列路径是拟定位置，M0 ADR
可调整并同步文档；命令尚不存在，不能当作本次已运行检查。

1. **M0-a：技术与隐私 ADR、契约 schema。** 只定框架/版本、目录、状态和版本清单；
   隐私单独 ADR 写清密钥、驻留、映射访问者和回注最小化。
   范围：`docs/adr/` 和最小 schema；验证：schema 合法/非法合成样例，版本缺项与
   hash 篡改负例，设计与字段逐项对照（V04）。无外部调用。
2. **M0-b：后端包和统一检查。** 最小类型化包、格式/lint/类型/单元检查及
   `Makefile`、CI。验证：从干净环境执行 `make check`；CI 执行同一命令。
   只有已存在的组件纳入检查，后续步骤加入集成/前端构建，不用空命令冒充通过。
3. **M0-c：数据库迁移与恢复夹具。** 只做迁移框架、最小实验清单持久化及测试数据库。
   验证：空库升级、合成快照升级、备份恢复（V02）；首个 schema 没有上一版时
   明确标为不适用，以后新增迁移必须补上一版兼容测试。
4. **M0-d：ModelProvider 契约和模拟实现。** 不接真实 SDK；固定成功、截断、超时、
   usage unknown 的 fixture。验证：契约正反例，禁用网络仍可运行（V01）。
5. **M0-e：API/worker 最小启动骨架。** 只做健康检查、独立进程入口与模拟调用演示；
   不开放临床操作接口。验证：启动/停止、模拟结果、无密钥无外连；检查日志无正文。
6. **M0-f：Web 最小壳。** 仅实验标识与后端连通状态，随后把类型、构建检查加入
   `make check`。验证：桌面/移动可打开，后端不可用显示确定状态，不嵌入模型密钥。
7. **M0-g：人工合成评测与最终门禁。** 版本化问题、预期行为、来源与事件族划分；
   工程可判定用例自动断言，医学判断保持待评审。50–100 是目标规模，不能为凑数
   自动制造真值。验证 V00–V04，记录样例数、未批准门槛、重复运行方式（V03）。

M0 全部退出条件满足后才进入 M1。M1 身份/证据 → M2 检索 → M3 状态机和预算
基础 → M4 编辑校验签发 → M5 患者文本闭环，继续沿用现有里程碑。M6 模态、M7
路由优化、M8 学习发布均保持延期，防止这一轮评估扩大为完整平台建设。
