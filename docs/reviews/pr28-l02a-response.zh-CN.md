## 逐项决定

- **F1（低）：采纳。** 依据成立，独立临时 Git 仓库复现忽略 pyc 未被默认 status
  报告。其影响是后续源码导入的基线不完整，运行前修复必要。`audit_source` 改为显式
  `--untracked-files=all --ignored`，同时防止本地 status.showUntrackedFiles=no
  隐藏未跟踪代码。任何额外文件均拒绝，不自动清理、不加宽允许名单。新增真实 Git
  回归覆盖忽略 pyc、忽略 py、被忽略目录中的 pth 以及被配置隐藏的未跟踪 py；fixture
  文件仅为合成文本，从未加载。设计约定实际导入加 `-B`，`-I` 不会保留相关环境变量。
  错误与预防规则记入 E18。
- **F2（信息）：采纳。** 两个来源的哈希一致，事实没有矛盾；增加直接来源能降低
  后续复核成本。设计文档保留固定 uv 元数据链接，并补官方 Python release 链接与
  digest。2026-11-17 只读查询官方 API，确认其资产 digest 与清单相同；没有重新下载。
- **F3（信息）：部分采纳。** 依据成立，包名/版本不能发现同版本已安装文件篡改。
  本次只改源码范围，不把它扩大为完整依赖取证。现在在设计中增加 L02b 首次执行前的
  完整性门禁：锁定 wheel 与安装内容独立比对，或从重新校验哈希的 wheel 新建受控环境；
  实现推迟到 L02b 的执行前准备，未完成前不将当前环境当作可信执行基线。
  当前脚本明确仍只审核 distribution metadata，未声称解决此项。
- **F4（信息）：跳过本切片实现，推迟到 L1/L3。** 日志不入库与尚无清理执行器的事实
  成立；但 512 MiB 是单实例 session 调试数据限额，不能用于判断整个源码/依赖目录。
  当前尚无 session，目录约 738 MiB 不等于调试配额超限。权限、容量和清理限制已写明，
  不需在源码审核修复中添加生命周期功能；由 L1 清理流程、L3 调试配额门禁承接。

合计：采纳 2 项、部分采纳 1 项、跳过本切片实现 1 项，无高严重度分歧。
