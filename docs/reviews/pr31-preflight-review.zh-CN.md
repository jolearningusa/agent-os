## 发现

### F1：安装后的文件内容没有与 wheel 比对（信息）

设计已写明：这证明安装输入来自锁定 artifact，不是已安装文件的完整性检查。若同一用户的
进程在安装后改写 site-packages，预检不会发现。对本切片可接受；L02b 要把该环境当作可信
基线时，建议在启动前重跑 artifact 与源码预检，并可考虑把已安装文件与 wheel 的 `RECORD`
哈希比对。

### F2：预检结果有时效（信息）

历史 pass 只代表检查那一刻。设计已要求执行器启动前重跑；实现执行器时应把它做成不可
绕过的门禁，而不是文档约定。

### F3：下载阶段依赖 bootstrap pip 的信任边界（信息）

下载由 bootstrap 里的 pip 24.2 完成，pip 本身未按哈希固定，只来自系统 Python 自带的
ensurepip。下载物仍受 `--require-hashes` 约束，风险有限；与 #26 的 F4 同类，可在建立
完整构建镜像时一并处理。

### F4：wheel 目录里的无关文件会让校验失败（信息）

`verify` 对任何不在索引中的文件都拒绝。我在测试中放入 `.DS_Store`，被正确拒绝。这是
失败即关闭，但 macOS 在 Finder 打开该目录就可能生成此文件。文档可补一句恢复方式：由
用户识别后删除无关文件再重跑，不要放宽校验。
